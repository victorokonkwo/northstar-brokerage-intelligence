| | |
|---|---|
| Status | **Not applied.** It will be applied only after the owner approves `make tf-plan-data` (CONTRIBUTING.md W6, AGENTS §8) |

This stack creates the cloud medallion's infrastructure. Every fact below is recorded in [`docs/sources.md`](../../../docs/sources.md).

| Resource | Settings |
|---|---|
| `aws_s3_bucket.bronze` (`northstar-bronze-<account>-<region>`) | **Bronze, the raw layer.** Private (public access blocked, bucket-owner-enforced), versioned with no expiry of old versions, SSE-S3, TLS-only. `terraform destroy` fails while it holds objects, which protects raw data |
| `aws_vpc.warehouse` and its 3 subnets, internet gateway, route table | **A dedicated VPC** for the workgroup's network interfaces: one public subnet in each of three AZs, and no NAT gateway |
| `aws_security_group.warehouse` | **Inbound:** TCP 5439 from Looker Studio's published range (`142.251.74.0/23`) and from the operator's address (`TF_VAR_operator_cidrs`) only. **Egress:** none, since without enhanced VPC routing, COPY from S3 doesn't use this VPC |
| `aws_redshiftserverless_namespace.warehouse` | **Database:** `northstar`, admin `nbi_admin`. **Admin password:** generated by Redshift and kept in Secrets Manager (`manage_admin_password`), rotated every 30 days by default; it is never in Terraform state or Git. **Default IAM role:** the COPY role |
| `aws_redshiftserverless_workgroup.warehouse` | **Capacity:** 4 RPU base and 4 RPU maximum, so it never scales up. **Access:** publicly reachable, but only through the security group, and `require_ssl = true`. **Port:** 5439 |
| `aws_redshiftserverless_usage_limit.daily` / `.monthly` | **Compute caps:** 4 RPU-hours a day and 60 RPU-hours a month. Breach action `deactivate`: Redshift turns off user queries until the period ends |
| `aws_iam_role.redshift_copy` | **COPY from bronze:** `s3:ListBucket`/`GetBucketLocation` on the bucket and `s3:GetObject` on its objects, nothing else. **Trust:** the two Redshift service principals AWS requires, limited to this account (`aws:SourceAccount`) |

Not in this stack:
- **Database users and grants.** The loader's insert-only grants come in 4F and the read-only `looker` user in 4G. Both are created with SQL, which avoids adding a Terraform provider for Redshift.
- **CloudWatch log exports.** Redshift's system views keep the connection and user logs.

## Cost (estimates from list prices, not a bill)

Prices are for ca-central-1 from the AWS Price List: the Redshift offer published 2026-09-11, and the VPC offer published 2026-11-19.

| Item | Price | Worst case under the caps |
|---|---|---|
| Compute | USD 0.4125 per RPU-hour; per second, with a 60-second minimum each time it wakes (4 RPU × 60 s = USD 0.0275) | daily cap: 4 RPU-hours = USD 1.65; monthly cap: 60 RPU-hours = **USD 24.75** |
| Managed storage | USD 0.0261 per GB-month | the dev dataset is well under 1 GB |
| Public IPv4 (the workgroup's Elastic IP) | USD 0.005 per address-hour, about USD 3.65 per address for a 730-hour month | AWS doesn't state how many addresses a workgroup gets; checked after apply |
| Secrets Manager (admin secret) | USD 0.40 per month | |
| S3 bronze | negligible at this size | |

**Free trial.** An account that has never used Redshift Serverless gets a USD 300 credit, valid for 90 days, toward compute and storage. Even three full months at the monthly cap (USD 74.25) stay inside it.

**The existing USD 10 budget.** Budgets include credits by default, so spend the credit covers doesn't count. The public IPv4 address and the secret aren't Redshift charges, so they count: with one address, about USD 4.05 a month. After the trial, compute counts too, so a month at the cap would trigger the budget alerts.

## Procedure

Run from the repository root, with `aws login` credentials for the account.

1. **Operator address.** Put your public IPv4 in the git-ignored `.env`, for example `TF_VAR_operator_cidrs='["203.0.113.7/32"]'` (see `.env.example`). Update it and re-apply whenever your address changes.
2. **Validate (no AWS access).** `make tf-validate`
3. **Plan.** `make tf-plan-data` writes `data.tfplan` (git-ignored). The owner reviews and approves it.
4. **Apply that plan, and only that plan.** The budget already exists (bootstrap stack):
   ```bash
   set -a && . ./.env && set +a
   terraform -chdir=infrastructure/terraform/data apply data.tfplan
   ```
5. **Read back** what AWS stored, and record it in the roadmap:
   ```bash
   aws redshift-serverless get-workgroup --workgroup-name northstar \
     --query 'workgroup.{base:baseCapacity,max:maxCapacity,public:publiclyAccessible,params:configParameters}'
   aws redshift-serverless list-usage-limits --resource-arn <workgroup arn>
   aws ec2 describe-addresses --filters Name=domain,Values=vpc
   ```
   Then run `make tf-plan-data` again; it should report no changes.
6. **Connect** with the admin secret: `aws secretsmanager get-secret-value --secret-id <redshift_admin_secret_arn>`. Never paste it anywhere tracked.

**Teardown.** `terraform -chdir=infrastructure/terraform/data plan -destroy -out=destroy.tfplan`, then the owner reviews and approves, then `terraform … apply destroy.tfplan`. Destroying the workgroup stops every compute and IPv4 charge. The bronze bucket must be emptied deliberately before it can be destroyed.

Nothing here is applied by CI. CI only runs `make tf-validate`.
